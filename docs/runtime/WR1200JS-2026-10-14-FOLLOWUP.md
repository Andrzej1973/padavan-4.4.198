# WR1200JS read-only follow-up, 2026-10-14

SSH to `ASUS@192.168.20.1` succeeded after the owner restored access. The
preceding timeout is not evidence of an Internet outage or reboot. Commands
only read runtime sources; no service was enabled, restarted or reconfigured.

The router reported Linux `4.4.198`, firmware `4.4.198.9`, uptime **3 days
2:05**, and load `0.07 / 0.03 / 0.02`. NVRAM `buildno` and `extendno` produced
no identifying value, so the installed CI artifact is still unidentified.
Uptime establishes continuous boot time at this observation, not uninterrupted
connectivity or acceptance of every subsystem.

- `stubby_enable=0`, `doh_enable=0`: intentionally disabled following recovery.
- `nslookup example.com 127.0.0.1` returned IPv4 and IPv6 answers. This proves
  that query worked at collection time; it does not validate DoT/DoH or clients.
- `zram_enable=1`; `/proc/swaps` contained only the header, `SwapTotal=0`.
  Requested ZRAM remains inactive in the installed image.
- `MemAvailable=57856 kB` at the snapshot.
- `/sys/module/usbip_core`, `usbip_host`, and `vhci_hcd` were absent; `pidof
  usbipd` returned no PID. No USB/IP activation or transfer was attempted.
- Local `GET /wr_devices.json` returned `{"error":"source_unavailable"}`.
  The installed integrated client collector remains unavailable despite earlier
  successful standalone diagnostic collectors.

Current CI images have not been installed by this work. New image runtime
verification, retained settings, actual ZRAM activation, integrated client
collection, driver/load behavior and reboot persistence remain open.
