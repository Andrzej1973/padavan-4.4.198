# ТЗ №01: Wi-Fi — спільні налаштування 2,4 / 5 ГГц

Це опис для малюнка й подальшої реалізації. Він не означає, що збереження
налаштувань уже працює. Роутер: YOUHUA WR1200JS. Усі решта сторінок,
підсторінок і діалогів також залишаються в обсязі Modern.

## Розташування й загальний вигляд

Зберегти затверджений стиль Modern: темне тло, наявна бічна навігація,
типографіка, кольори й картки. Не створювати окрему візуальну систему.

Заголовок: **Бездротова мережа**. Під ним вкладки:
**Спільні** · **Окремі діапазони** · **IoT 2,4 ГГц**.
Активна вкладка позначається кольором і підписом, а не лише кольором.
Пункт IoT лишається видимим; він відкриває окремий розділ «У розробці».
На цій сторінці немає перемикача ввімкнення IoT.

Основний вміст: спочатку короткий опис, далі картка режиму, картки збережених
даних двох діапазонів, форма спільних даних і панель дій. На широкому екрані
картки діапазонів стоять поруч, на телефоні — одна під одною.

## Картка «Одна назва й захист для двох діапазонів»

Перемикач: **Спільні SSID та захист для 2,4 і 5 ГГц**.
Пояснення: «Обидва діапазони використовуватимуть однакові назву мережі та
параметри захисту. Канали, ширина, розклад, гостьові мережі та ввімкнення
кожного радіомодуля налаштовуються окремо».

Зміна перемикача лише редагує чернетку. Вона нічого не застосовує одразу.
Якщо режим вимикається: «Поточні назви й паролі обох діапазонів буде збережено».
Не показувати тут один загальний перемикач живлення двох радіомодулів.

## Дві картки «Збережено: 2,4 ГГц» та «Збережено: 5 ГГц»

Показати SSID, метод захисту та збережений стан радіо. Пароль не показувати.
Під картками: «Збережені налаштування. Це не підтвердження фактичного стану
підключень». Для невідомого значення показати «Невідомо», а не зелений статус.

Коли спільний режим уперше вмикається, дати явний вибір вихідних налаштувань:
**Взяти за основу 2,4 ГГц** / **Взяти за основу 5 ГГц**.
Не копіювати дані другого діапазону без вибору й підтвердження.
Обраний діапазон буде джерелом спільних параметрів, а не пріоритетом радіо.

## Форма «Спільна назва й захист»

| Елемент | Як намалювати / поведінка |
|---|---|
| Назва мережі (SSID) | Однорядкове поле; допомога про ліміт 32 байти UTF-8; живий лічильник, без обрізання Unicode |
| Захист | Відкрита мережа / WPA Personal; WPA3 тут не додавати |
| Версія WPA | WPA2, WPA/WPA2, WPA — лише у WPA Personal; зберігати сумісність чинних значень |
| Шифрування | AES, TKIP, TKIP + AES — лише у WPA Personal |
| Пароль | Явний вибір «Залишити без змін» / «Встановити новий»; нижче нове поле лише для другого варіанта |
| Новий пароль | Масковане поле; показати/приховати лише введений новий пароль; порожнє поле не означає стерти збережений ключ |

При відкритій мережі показати зрозуміле попередження про відсутність захисту.
Наявні WEP/Enterprise або невідомі режими не перетворювати автоматично на WPA
Personal. Показати збережений режим і пояснення: для переходу до спільного
режиму потрібно явно вибрати сумісний захист. Повні окремі сторінки мають
зберегти всі підтверджені можливості Classic; ця форма не замінює їхню повноту.

Не додавати сюди канали, потужність, ширину, розклад, приховування SSID,
Beamforming, CAKE чи налаштування гостьової/IoT мережі.

## Панель дій

**Скасувати зміни** — повернути останні завантажені значення, очистити новий
пароль, нічого не записувати на роутер.
**Перевірити й застосувати** — спочатку локальна перевірка, потім діалог.
Поки не готовий backend, замість активної кнопки показувати «Збереження
в Modern ще розробляється» та наявний перехід Classic.

Діалог підтвердження:

- Заголовок «Застосувати зміни Wi-Fi?».
- До/після для SSID, захисту та спільного режиму; окремо зазначити обидва
  діапазони. Пароль не дублювати: лише «без змін» або «буде змінено».
- «Wi-Fi з’єднання може перерватися. Після зміни назви або пароля потрібно
  повторно підключитися». Не обіцяти збереження асоціацій при зміні Wi-Fi.
- Кнопки «Повернутися» і «Застосувати». Повторне натискання блокується.

## Стани, які потрібні на малюнку

1. Завантаження — нейтральні заглушки полів, без вигаданих SSID/паролів.
2. Завантажено, змін немає — кнопка застосування недоступна.
3. Чернетку змінено — помітка «Є незбережені зміни».
4. Помилка поля — текст біля поля, фокус на першій помилці; не лише червона рамка.
5. Не вдалося завантажити — повідомлення, «Повторити» та перехід Classic;
   збереження недоступне. Не підставляти DEMO-дані.
6. Запит надсилається — індикатор, заборона повторного запиту.
7. Втрачено зв’язок під час застосування — «Результат ще не підтверджено»,
   інструкція повторного підключення. Не показувати «Успішно» лише через таймер.
8. Сервер відхилив запит — збереження не заявляється; пароль очищається;
   текст помилки не містить секретів.
9. Підтверджений результат — показати лише після належної відповіді/повторного
   читання; фактичну працездатність Wi-Fi відокремити від збереження конфігурації.

## Мобільність і доступність

На телефоні одна колонка, поля на всю ширину. Кнопки не перекривають вміст
і фокус. Усе доступне клавіатурою; підписи пов’язані з полями; діалог повертає
фокус. При переході між вкладками не зберігати зміни й не копіювати налаштування
автоматично. Новий пароль не зберігати в URL, localStorage, логах або підказках.

## Межі реалізації для розробника

Наявний shared backend підтримує відкриту мережу без WEP та WPA Personal.
SSID: 1–32 байти UTF-8; PSK: 8–63 байти або 64 шістнадцяткові символи.
Форма має використовувати чинний CGI/NVRAM/RC apply, зберігати обидва діапазони
та не послаблювати відхилення неповних Classic-запитів.

Читання публічних полів уже реалізоване локально; явне збереження ключа,
робоча форма Apply та її feedback ще не реалізовані. Джерела:
`docs/WR1200JS-MODERN-WIFI-APPLY-CONTRACT.md`, `tools/shared-wifi/plan.h`,
`adapter.h`, `validate.h`, `tools/webui-preview/wr-modern-http.inc`.
Макет сам по собі не є доказом backend, образу або роботи на пристрої.
