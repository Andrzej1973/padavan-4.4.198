# Спільний план перенесення корисних рішень

Доручення користувача, 2026-10-14: використати найкращі придатні рішення з усіх
вже досліджених баз. Критерій — стабільність, збереження доступу й конфігурації,
підтримка WR1200JS і перевірюваність. Сам номер версії не є критерієм якості.
Цей план доповнює PROJECT-DELIVERY-SCOPE.md, не замінює повне приймання порту.

## Джерела й рішення

- **Nilabsent / Linaro / Alxdm:** робочі сторінки та життєвий цикл DNS/VPN,
  каталоги провайдерів, локалізація, backup/storage. Пріоритет — зберегти
  робочу поведінку. Поточні DoT/DoH, AmneziaWG та OpenSSL-порти вже включені;
  перевірки образів не закривають реальні start/stop, TLS, маршрути й reboot.
  Див. SERVICE-PORT-AND-SETTINGS-AUDIT.md і DNS-DOT-DOH-LOCALIZATION-AUDIT.md.
- **Hadzhioglu:** ndisc6, socat, USB/IP та залежності — переносити лише відсутню
  інтеграцію вибраних функцій. USB/IP уже збирається з відповідних Linux 4.4
  джерел і libudev; старий варіант Linux 3.4 + sysfsutils не підміняє його.
  Керування USB/IP, firewall, експорт і persistence ще відкриті.
  HADZHIOGLU-CANDIDATES.md зберігається як історичний список; перевіряти
  кожен його пункт проти поточного 4.4 дерева, а не повторно імпортувати пакети.
- **hanwckf / MeIsReallyBa / vipshmily / TurBoTse:** зберегти базу 4.4.198,
  board/DTS, перевірений toolchain, offload і базовий WebUI. Подальші driver
  зміни переносити вузько; не замінювати базу цілком і не вважати форки
  незалежними підтвердженнями, коли вони успадковують однакові Git blobs.
- **tsl0922 / yummy026:** закріплені рецепти пакетів, source hashes, staging,
  окремі цілі збірки та optional ttyd/SmartDNS. ccache вже використовується.
  GCC 13/uClibc — окремий кандидат із перевіркою kernel, legacy radios і всього
  ELF closure; musl не змішувати з uClibc. Не знижувати наш OpenSSL заради донора.
- **padavan-fusion:** використати послідовність WebUI → variables → профіль
  для k/v/r, але лише для дійсно підтримуваних драйверів. Не переносити знайдену
  помилку fprintf і не вмикати k/v/r фабрично без апаратної перевірки.
- **soulherats:** збережені WR1200JS GPIO/радіо-reference та k/v/WPA3-кандидати.
  Залишити фізичні 128 MB; конфіг 512 MB і прапорці WPA3 без доведеного
  build/runtime шляху не є придатними налаштуваннями нашого пристрою.
- **xiaobei207:** MT76x2 file-read guard, WireGuard compat і окремий аналіз
  HWNAT queue/binding. Деталі й точні SHA: XIAOBEI207-PADAVAN44-AUDIT.md.

## Черга впровадження

1. Вузькі виправлення помилок із наявних донорів: MT76x2 invalid-handle guard
   тепер підключений до підготовки нормальної WR1200JS-збірки. Наш варіант
   перевіряє NULL та ERR_PTR до обох шляхів читання; походження збережене
   в tools/prepare-mt76x2-file-read.py. Очікуються native CI, реальна MIPS
   компіляція й апаратна перевірка; це не заявлений fix Wi-Fi/HWNAT зависання.
2. Закінчити поточні прийняті IoT/Wi-Fi/служби: використати робочі donor
   implementation units разом із backend, меню, перекладами, статусом,
   залежностями та persistence. Не залишати лише кнопки без робочої служби.
3. WireGuard compat: зіставити реальні зміни upstream і наш AmneziaWG ABI,
   перевірити пакування, handshake, маршрути та навантаження перед заміною.
4. HWNAT: окремо розібрати M2Q_table, межі mark, FOE binding і фактично обраний
   kernel driver. Зберегти нашу політику Wi-Fi acceleration до доказу поліпшення.
5. Після WR1200JS — Mi Mini, потім узгоджена робота offline/toolchain/databases.
   StrongSwan залишається на фінальній стадії за рішенням користувача;
   Tor/Zapret/OBFS4 — у погодженій наступній стадії. CAKE виключено.

## Умови прийняття кожного перенесення

Зафіксувати джерело та ревізію, пояснити конкретну користь, перевірити різницю
з нашим поточним деревом і ліцензію компонентів. Переносити потрібний код разом
із залежностями, capability gates, перекладами й інструкцією. Перевірити
помилки/відновлення, фактичні файли образу, розмір і незмінність запитаного
профілю. Окремо позначати source, build, emulation і physical evidence.

Не імпортувати розгін, надмірні буфери, небезпечні workflow triggers,
рухомі залежності та видалення атрибуції. Реєстр кандидатів означає включення
в роботу; завершеним є лише пункт із доказами відповідного рівня.
