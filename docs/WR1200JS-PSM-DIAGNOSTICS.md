# MT7603 PSM/DTIM diagnostics

Source inspected: vendor mt76x3 c25283e915a2a00a763774dd255b14aff997285e.
This is owner-authorized diagnostic validation; no device operations are authorized by it.
No router commands, firmware install, driver-policy or timing changes performed.

## State and buffering

ap/ap_data.c:ap_rx_ps_handle and tx_rx/wdev_rx.c feed received PwrMgmt to
common/ps.c:RtmpPsIndicate -> common/mt_ps.c:MtPsIndicate for HIF_MT.
MtPsIndicate bounds-checks WCID, retains old PsMode, resets NoDataIdleCount,
updates both MAC entry and TR entry PsMode. SAVE->ACTIVE triggers retrieval/
PS-poll servicing when ps_state is APPS_RETRIEVE_DONE; other retrieval states
have separate handling. UAPSD/QoS triggers and MT retrieval are not equivalent
to one global sleep flag. A Null frame can change PS state without payload.

ap/ap_connect.c APUpdateBeaconFrame writes TIM DTIM count/period and STA TIM
bitmap; multicast/broadcast bit is inserted when DtimCount==0. The shared
APUpdateAllBeaconFrame advances DTIM count and updates BSS beacons. DTIM does
not require every sleeping unicast client to ACK each beacon; buffered unicast
also depends on TIM/PS-Poll/UAPSD/retrieval. Do not equate modem sleep with a
slow immediate hardware ACK response.

Concrete drop/association candidates:
- ap/ap_data.c PS enqueue checks four AC queue lengths against
  MAX_PACKETS_IN_PS_QUEUE; common/ps.c and cmm_data.c have additional PS queue
  capacity gates. These are distinct drop paths and not all instrumented here.
- ap/ap.c maintenance clears TX software queues and TIM after PsQIdleCount>2
  when sleeping, retrieval DONE/IDLE and enqCount>0. Threshold is maintenance
  invocations, not a measured seconds deadline without scheduler evidence.
- ap/ap.c age-out: TxSucCnt==0 and NoDataIdleCount>=StaIdleTimeout leads to
  disconnect. Sleep transition itself is not an unconditional disassociation.
- MT7603 TxS format0 contains ME/RE/LE/BE and raw mpdu_tx_cnt. Raw transmit
  count is not automatically retries; report coverage is not all transmissions.

No evidence yet establishes that these policies prematurely drop the owner's
ESP clients. Correlate event timestamps with client sleep/traffic and monitor
captures before changing queue aging, DTIM or station timeout.

## Patch

`docs/patches/WR1200JS-MT7603-PSM-DIAGNOSTICS.patch` is generated by
`tools/iot/prepare-psm-diagnostics.py DRIVER_ROOT OUTPUT.patch`.
Apply from an isolated pinned driver root using `git apply --check` then
`git apply` with the absolute patch path. It is not applied to production.
It adds a header and hooks in common/mt_ps.c, ap/ap.c, ap/ap_connect.c,tx_rx/txs.c.

Default OFF. Compile selected diagnostic driver with `-DWR_IOT_PSM_DIAG`
added to its Kbuild compiler flags; do not change firmware protocol/ACK guards.
Use existing GitHub standard then exact-SHA peer82 candidate workflow for full
MIPS module builds. This patch has clean-apply verification only so far, not
full target compilation or runtime acceptance. Integrating in the layered
candidate needs explicit manifest/source-anchor updates; do not apply blindly
after generators that rewrite these same functions.

When enabled, `dmesg` lines prefixed `wr_ps` expose:

| event | bss/peer | x | y |
|---|---|---|---|
|0 PSM transition|BSS index/WCID|old PS mode|new PS mode|
|1 PS queue aging purge attempt|BSS index/WCID|PsQIdleCount|enqCount before cleanup|
|2 age-out decision|BSS index/WCID|NoDataIdleCount|StaIdleTimeout|
|3 TIM construction|BSS index/unused|DTIM count|DTIM period|
|4 received TxS format0|unknown BSS/WCID from report|ME bit0, RE bit1, LE bit2, BE bit3|raw MPDU transmit count|

No MAC addresses, passwords or packet payload logged. Event4 WCID is not
looked up: this avoids stale report attribution to a recycled peer. Unknown
BSS prints unsigned all-ones. It is NOT per-BSS retry measurement.
`hits` is an atomic per-event, per-translation-unit counter of hook invocations,
wrapping at32bits; suppressed log lines still count. Header site labels identify
the diagnostic version, not unique adapters. Rate limiter caps output to8 lines
per5seconds per translation unit, shared across its event types. Consequently
lines are samples, not a complete event ledger, and busy DTIM logging can hide
other lines. No quantitative radio retry/drop percentage can be derived solely
from this trace. Separate adapters share each translation-unit counter.

For actual rates use paired snapshots of existing driver statistics plus traffic
counts over an interval, respecting counter reset/wrap and global/per-peer scope.
The source exposes `show` handlers `stainfo`, `peerinfo`, `stat` in ap/ap_cfg.c;
confirm those handlers are registered in the exact built image using
`iwpriv ra0` before using `iwpriv ra0 show stat` / `show stainfo`. Some stat
handlers/register reads can reset counters: audit the selected handler first.
These commands are proposed runtime diagnostics, not executed here.

## Validation and acceptance

1. Confirm disabled build has no emitted hook side effects or new TXS requests.
2. Compile enabled/disabled MT7603 MIPS targets, include actual kernel4.4 API
   compatibility and all affected TU guards. Inspect module/source hashes.
3. With authorized device session, bounded capture of client sleep/wake, idle
   intervals and traffic bursts, Main/Guest/IoT concurrently. Compare enabled
   versus disabled logging for latency, CPU/log volume and disconnects.
4. Correlate PS event0, event1 purges, event2 age-out, DTIM event3 and received
   event4 reports with independent packet/traffic counters. Check PS queue-full
   and retrieval failure paths separately; absent logs are not proof of absence.
5. Only then consider scoped aging/power-save fixes. Do not disable ACK, change
   SIFS/slot or extend STA idle timeout as an unproven blanket workaround.

## Owner-authorized OFF/ON build verification

`ci-compile-psm-diagnostics.sh` runs after peer82 baseline and existing feature
checks. It copies the prepared kernel into a disposable CI directory, generates
and applies the patch against the actual accumulated driver, builds complete
MT7603 modules OFF/ON, preserves both modules/commands/logs, checks MIPS ELF,
config invariance and absence/presence of the diagnostic format string. It
removes the disposable source tree afterward; no module is installed in ROMFS.
`check-psm-diagnostics.py` executes the actual generated header under gnu89 with
injected kernel atomic/ratelimit APIs: OFF arguments are not evaluated; ON output
is bounded and invalid event index refused. Native ASan/UBSan tests pass.
Pinned-source and current API-successor clean patch application pass. Actual
kernel atomics/locking and target APIs remain for the full GitHub module builds.
