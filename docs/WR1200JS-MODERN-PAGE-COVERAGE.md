## Implementation and acceptance order

Sol remains sole writer in the existing shared checkout. Preserve settings,
Classic recovery access, Band Steering, board capabilities and the IoT reservation.
IoT remains mandatory for release and its driver blockers remain separate.

1. Map every document and helper to its function and parent; reconcile dynamic
   navigation, dialogs and overlay-generated pages. This file inventories shipped
   HTML/ASP, so it does not yet prove all JavaScript-created dialogs are listed.
2. Implement complete Modern Wi-Fi main/guest/common/professional pages using
   existing validation, CGI/NVRAM and RC paths. Keep IoT controls unavailable
   until its real lifecycle/isolation backend is accepted.
3. Implement the remaining WAN/LAN, IPv6/DHCP/DNS, VPN, services, USB/storage,
   firewall/QoS, monitoring/logs and system/administration functions, including
   dialogs, validation, save/apply feedback and mobile/keyboard operation.
4. Require per-page host/browser checks, target/ROMFS/final-image evidence and
   separately authorized device acceptance. A linked Classic page is interim
   navigation, not completion of its Modern replacement.

Rows are conservative: `not accepted` does not erase existing overview/model/
read-only-shell tests. It means complete per-page functional equivalence has not
been established. Unsupported board features must remain absent/inert, and
inventory alone cannot establish support. CAKE remains excluded. Do not restore
unsupported inherited controls merely because a Classic file is shipped.
