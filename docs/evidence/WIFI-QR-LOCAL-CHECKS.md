# Local Wi-Fi QR checks (2026-10-08)

These checks use synthetic credentials only. The QR preview is not yet wired into the production build.

- Payload checks cover UTF-8 length limits, escaping, hidden and open networks, personal security, and rejection of unsupported modes.
- The actual renderer UTF-8 constructor matches UTF-8 bytes without a BOM and does not expose credentials in an element title.
- Five matrices generated by the renderer public constructor decoded byte-for-byte with independent zxing-cpp 2.3.0: ASCII, Ukrainian plus emoji, escaped punctuation and hidden SSID, open security, and maximum supported SSID/password lengths.
- Edge Chromium rendered the full local renderer on a synthetic form. Its screenshot decoded byte-for-byte with the independent decoder. Editing input or pressing Hide removed the QR; unsupported enterprise security displayed a generic error. No page errors or requests occurred.
- Preparation succeeded on both pinned upstream main Wi-Fi pages and EN/UK/RU dictionaries. Repeated preparation refused without changing any file.

## Remaining acceptance

Production page layout, authenticated access, image inclusion, phone interoperability and connection, and the optional shared configuration backend remain unverified or unimplemented. This evidence does not prove router runtime behavior.
