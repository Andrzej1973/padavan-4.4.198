# IoT v21 recovery and PCI remove call graph, 2026-10-28

Scope: source audit of the isolated 67-file v21 candidate. No driver was installed, built for MIPS or run on the router.

The failed main VERIFY branch in `os/linux/rt_main_dev.c` now attempts synchronous checked close under the `ndo_open` RTNL context. On incomplete close it retains the module pin and returns failure. The kernel will not subsequently call `ndo_stop` for that failed open. The callback `wr_iot_main_recovery_work_fn` exists, and the owner header contains queue, schedule-result, retry, and complete state helpers, but a candidate-wide search of C/H call sites finds **no caller** of `wr_iot_main_recovery_queue`, `wr_iot_main_recovery_queue_close`, `wr_iot_main_recovery_schedule_result`, `wr_iot_main_recovery_requeue`, or `wr_iot_main_recovery_complete`. There is no `schedule_work` call for `wr_iot_main_recovery_work`. Thus the retained owner cannot currently progress to a recovery callback.

`os/linux/pci_main_dev.c` calls `wr_iot_main_recovery_request_stop`, joins the work with `cancel_work_sync`, and returns early if `deferred_owners` is still set. It has no post-join call to `wr_iot_main_recovery_complete` and no separate deferred PCI-release owner in this candidate. A second join follows `RtmpPhyNetDevExit`, with the same early-return check. Other readiness and PCI config-observation failures also return before adapter/CSR release. These returns preserve live memory rather than freeing it unsafely, but this source has no subsequent owner path that finishes the removal. PCI `remove` is a void callback; these returns are not a proven retry protocol. Treat teardown as blocked, not completed.

The worker executor calls checked close without RTNL admission. The PCI remove path joins it before `RtmpPhyNetDevExit`; netdevice unregister may take RTNL. A proposed worker that simply blocks in `rtnl_lock` can also deadlock if a remover or another teardown caller already holds RTNL while waiting in `cancel_work_sync`. A proposed `rtnl_trylock` avoids that wait edge but needs an explicit retry/retained-owner path and lifetime proofs. No such alternative has been bound or tested here.

Required joint fix before production: capture the exact failed-open or partial-close ticket and record under the transition lock; hold the netdev and fence adapter release before queueing; record `schedule_work` acceptance; arrange RTNL-safe execution without a join cycle; handle rejected scheduling and bounded retry with a joined prior work item; release the module pin only after checked close; have PCI removal join and account for the owner, quiesce callbacks, and complete release exactly once. The fix must cover both normal and retirement admissions. It needs fault-injected host tests, target compilation, image gates, and separately authorized device acceptance. The current v21 candidate proves none of those end-to-end properties.
