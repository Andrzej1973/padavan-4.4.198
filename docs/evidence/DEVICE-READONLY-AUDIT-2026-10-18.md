# Частковий read-only знімок пристрою — 2026-10-18

Перевірка виконана через SSH до YOUHUA WR1200JS. Усі команди лише читали стан;
конфігурацію, служби й радіо не змінювали. Значення, що можуть розкривати
секрети чи ідентифікатори мережі, не запитувалися або не публікуються.

## Спостереження

| Область | Результат | Межа висновку |
| --- | --- | --- |
| Ідентичність | productid=WR1200JS, uname -r=4.4.198 | Точний firmware build/commit не визначений цим запитом. |
| Час роботи | Приблизно 87 047 секунд на момент знімка | Одноразове значення, не вимір стабільності. |
| Wi-Fi | ra0 і rai0 мають operstate=up; обидва приєднані до br0 | Підтверджено стан інтерфейсу, не радіоякість чи клієнтський трафік. |
| Міст | br0 показує eth2, ra0, rai0 | Знімок складу мосту на час перевірки. |
| ZRAM | /dev/zram0 у /proc/swaps: 30 912 КБ, використано 0 КБ | Swap активний; це не стрес-тест пам'яті чи перевірка компресії. |
| Базові процеси | dnsmasq і dropbear мають PID | Не перевірено повний DNS/DHCP чи SSH-клієнтський сценарій. |
| DNS-служби | stubby і https-dns-proxy не мають виявленого процесу | Відповідає спостереженню про вимкнені сервіси; причина та їхні конфігурації не досліджувалися. |
| ZeroTier / Privoxy / Shadowsocks | zerotier-one, privoxy, ss-redir, ss-local не мають виявленого процесу | Миттєва перевірка процесів не визначає, чи служби зібрані/налаштовані. |
| WireGuard / AmneziaWG | wg show interfaces повернув wg1; модуль amneziawg завантажений | Інтерфейс і модуль існують; handshake, маршрути, DNS і передача трафіку не перевірялися. wg/awg є утилітами керування, тому їх відсутність серед daemon-процесів нічого не доводить. Тип конфігурації wg1 цим не визначено. |
| IoT MBSS | ra2 відсутній у /sys/class/net | Не доводить відсутність підтримки в образі; стан activation path потрібно перевірити окремо. |

## Що цей знімок не підтверджує

Це не наскрізна перевірка інтернету, WAN, DNS-відповідей, DHCP-оренди,
VPN-handshake, швидкості, вебінтерфейсу, клієнтського списку, збереження
налаштувань після reboot або відповідності саме останньому образу #457. Не
виконувалися перезапуск, перезавантаження, прошивання чи будь-які зміни стану.
Для точного зіставлення з білдом потрібне окреме безпечне читання firmware
build ID із пристрою та порівняння з артефактом.
