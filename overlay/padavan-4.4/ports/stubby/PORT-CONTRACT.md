# Stubby port contract

Inspected 2026-10-02. Original pinned firmware: nilabsent/padavan-ng d2c5846299949c57a4e867284069900b561dd2a4.

Official GitHub latest release APIs: getdnsapi/stubby v0.4.3 and getdnsapi/getdns v1.7.3. These match the original firmware recipes; there is no newer official release established by this check.

Use the official getdns source tarball, not GitHub autogenerated archives (upstream explicitly requests this):
https://getdnsapi.net/dist/getdns-1.7.3.tar.gz
SHA256 f1404ca250f02e37a118aa00cf0ec2cbe11896e060c6d369c6761baea7d55a2c
Source: https://getdnsapi.net/releases/

getdns stub-only/IDN2-off builds need OpenSSL without recursive libunbound. Stubby additionally requires libyaml; original firmware has yaml 0.2.4 static. Verify target staged OpenSSL 3.5 linkage and cross-CMake search paths instead of allowing host dependencies. Keep performance flags inherited.

Preserve requested behavior and settings:
- Default stubby_enable=0; listen port 5453, listen mode 0 (127.0.0.1).
- Modes 0/1 strict TLS authentication and TLS-only transport; modes 2/3 opportunistic TLS/UDP/TCP. Do not silently convert a user's strict mode to fallback plaintext.
- Resolver server0..3, IP0..3, round_robin and mode fields must all round-trip through NVRAM/WebUI. Original defaults lack stubby_server_ip3 even though script reads it: inspect migration before adding an empty default.
- LAN and wildcard listener modes must preserve intentional firewall behavior; do not enable wildcard by default.
- Runtime generated configuration /etc/storage/stubby/stubby.yml, runtime PID /var/run/stubby.pid.
- Preserve DNS integration/restarts, CA certificates, accurate clock requirements, resolver list dot.json and UI file handling.

Old helper issues to resolve before reuse:
- `pgrep -x /usr/sbin/stubby` compares a path to a process name on common implementations; use verified PID/name handling.
- Startup invokes `stubby -i` and `stubby -g` without explicit config path; confirm actual compiled default path or provide the generated configuration explicitly.
- Stale PID file is treated as running; no liveness check.
- Server/IP inputs are interpolated into YAML without validation; validate and quote appropriately.
- Stop unconditionally SIGKILLs the service; retain a graceful lifecycle and verified exit behavior where supported.

Outstanding: inspect all native lifecycle/dnsmasq/firewall/WebUI paths; pin Stubby/libyaml source hashes; cross-compile with current OpenSSL; image packaging and closure; TLS query/runtime behavior. No Stubby image support is claimed yet.

## Package recipe draft — 2026-10-03

`Makefile` builds bundled Stubby 0.4.3 from the checksum-pinned official
getdns 1.7.3 archive. It requires staged static libyaml and target OpenSSL,
isolates CMake target-library searches, disables systemd, and inherits the
firmware's optimization flags. getdns is built within this package, so this
route does not require the separate libgetdns recipe to be registered too.

ROMFS copies are explicit: binary `/usr/sbin/stubby`, service helper
`/usr/bin/stubby.sh`, and resolver list `/www/dot.json`. Upstream install is
not used to seed live storage or overwrite existing configuration.
The helper and resolver list must be supplied before registration; this is
an incomplete integration candidate, not a runnable firmware package yet.

The standalone CI probe in build 85 is still running at firmware compilation.
Actual bundled binary path, cross-link closure and libyaml discovery must be
confirmed from that probe before integrating the package. Remaining service,
NVRAM, DNS and WebUI work is unchanged.

## Lifecycle prerequisites checked — 2026-10-03
Pinned 4.4 trunk/configs/boards/busybox.config enables CONFIG_FLOCK, CONFIG_PIDOF, CONFIG_AWK and CONFIG_ASH, but CONFIG_MKTEMP is disabled. The integration must enable CONFIG_MKTEMP for CONFIG_FIRMWARE_INCLUDE_STUBBY=y and verify the effective BusyBox config and ROMFS applet. The draft helper is not ready for registration until this prerequisite is supplied. fd9 locking must be closed on the daemon launch to avoid a child holding it indefinitely. Upstream -i is a syntax/context validation only: it does not prove TLS authentication, network reachability or a working DNS query.

## Original backend behavior inspected — 2026-10-03

Original `rc/services.c` starts Stubby only outside AP mode and when
`stubby_enable=1`; shutdown stops it. Preserve these gates and expose restart
through the dispatcher. The new helper's restart must stay one serialized
operation, rather than separate unlocked stop/start invocations.

`rc/services_ex.c` routes dnsmasq through Stubby only for modes 1 and 3.
Modes 0 and 2 are standalone listeners. Strict versus opportunistic transport
is a separate distinction: modes 0/1 require authenticated TLS; 2/3 permit
TLS/UDP/TCP. Preserve all four combinations.

For routing modes, original code emits `server=<listener>#<port>` and
`no-resolv` when a configured resolver pair is found. Do not condition
`no-resolv` on daemon liveness: a stopped strict-mode daemon must not silently
restore ordinary upstream DNS. Inspect all other dnsmasq server directives,
bootstrap paths and firewall rules before claiming this invariant holds.

Original HTTP fields request Stubby restart for resolver/name/IP and round
robin changes; enable/port/listen-mode/privacy-mode changes also restart
dnsmasq. The original event table associates Stubby restart with firewall
restart. Preserve the intended effect after inspecting current masks; do not
reuse bit numbers from the old base without collision checks.

`nvram-schema.json` records 13 defaults with the original key names and
values, adding an empty `stubby_server_ip3` because both original helper and
HTTP fields already use it. This schema does not overwrite stored user values.


Original rc.c also starts Stubby during boot, dispatches RCN_RESTART_STUBBY, and restarts DHCP/DNS after clock synchronization when encrypted DNS is enabled. This is part of the required port: authenticated TLS needs a correct clock, so inspect and preserve the narrowly scoped NTP bootstrap DNS handling in services_ex.c. Do not claim strict DNS closure before auditing these intentional exceptions. net_wan.c and firewall_ex.c contain no direct Stubby references in the inspected original source.
